**Status:** done (2026-09-29), on branch `replatform-phase-6`, which is based on `replatform-phase-5`. **Resume
point:** Task 8, the merge into `main`, which waits on the owner; read **Findings from Phase 6** at the end of this
file first. **Requires Phase 5 done** (it is, 2026-09-29).

**Goal:** The owner composes Home in the backoffice from a Block List of three blocks: rich text, card grid and
stacker. Every block shares one settings element, for its section's background and width. The baseline home is
re-authored in those blocks from the Xperience home, and re-exported, so every fresh database boots into it. The page
follows the brand: its text sits on torn sheets, and its sections sit a section apart. The gate: Home in both ramps
against the reference, the brand steward's review, and then `replatform` merges into `main`.

**Architecture:** Two one-off, dev-only bootstraps do the authoring, the way Phases 1 and 2 did, against a fresh
Development database in a throwaway folder, never the owner's:
- The first creates five element types (`card`, `sectionSettings`, `richTextBlock`, `cardGridBlock`, `stackerBlock`),
  eight data types and `homePage.sections`. uSync exports them on save, and ModelsBuilder writes their models.
- The second writes the Xperience home's content into Home as six sections, and the baseline export writes
  `uSync/v17/Content/home.config`.

Both are committed once and then deleted. `HomePageController` maps `HomePage.Sections` onto first-party section
records (`HomeSections`, with `SectionStyle` turning the settings into classes). `Index.cshtml` renders one Razor
partial per block: `<Card>` and `<Stacker>` from the existing components, and hand-written torn sheets for editor text,
with every editor string kept out of the Vue compiler. A new kit class, `kcc-prose`, gives editor rich text its rhythm.
The Page Builder's leftover margin and column CSS goes.

**Tech Stack:** Umbraco.Cms 17.x (the version Phase 1 pinned): Block List, the Tiptap rich text editor, ModelsBuilder
`SourceCodeManual`, uSync 17. Vue 3 SSR, Tailwind 4, TUnit 1.27 + Moq, Microsoft.AspNetCore.Mvc.Testing,
TUnit.Playwright, Vitest, and `tests/KCC.ReferenceCapture`.

**Spec:** `docs/replatform/specs/2026-09-21-replatform-off-xperience.md`. Sections: §6.4 (the widget output cache
disappears), §7 (the blocks, `card`, `sectionSettings` and the one-language model), §11 (the editing experience),
§12 (the baseline, "re-exported whenever it changes, as in Phase 6"), §14 (testing), §15 (the Phase 6 row, its gate
and the merge into `main`) and §16 item 1 (what Block List gives up against Page Builder). Task 7 corrects §7 and §16
to match what this phase builds.

## What the scratch probe already proved

Everything below ran in a clone of `replatform-phase-3` at `4d57ca1`: Phases 1 and 2 as built, and Phase 3's Tasks 1
and 2, on Umbraco 17.7.0 and SQLite. The brand steward reviewed the prototype in four rounds, and the owner settled
three design questions along the way (see "The brand review" below). Tasks 1 to 5 of this plan then ran in order in a
clean clone of that commit, with this plan's code blocks as written. The run was green:
- 176 unit tests (33 new), 129 integration tests (34 new) and 23 E2E tests (4 new);
- 754 Vitest tests (1 new), the type check, and `yarn format`, which changed nothing;
- warnings as errors, with StyleCop on.

The findings:

- **A throwaway Development site** keeps the owner's dev database out of this phase entirely.
  - `ASPNETCORE_ENVIRONMENT=Development` keeps the dev-only endpoints, uSync's export on save and `SourceCodeManual`
    models.
  - `ASPNETCORE_VITE=false` is required. `UseVueSsr` parses the variable in Development, and no Vite dev server
    starts.
  - On a fresh database in its own folder, the site reaches Run in about 10 seconds, and its first boot writes nothing
    into the repository.
- **A property on an existing type.** `IContentType.AddPropertyType(propertyType, "home", "Home")` creates the group
  with a random key, so the bootstrap replaces it with a deterministic one before `IContentTypeService.UpdateAsync`.
  In the backoffice the Home group sits above the composition's Metadata group.
- **Block labels.** `BlockListConfiguration.BlockConfiguration` models only the two element keys, so a block's
  `label` goes into the configuration dictionary as plain JSON; the backoffice renders it as UFM.
  - `{=text | stripHtml | truncate:60}` shows a rich text block's first 60 characters, with an ellipsis.
  - The filter aliases are camelCase: 17.7 marks the hyphenated ones (`strip-html`) for removal in 18.
  - `fallback` replaces only an empty string, never a value that was not set. With it, a card grid without a
    heading showed a blank label, so the labels name the block's type instead: `Card grid: {=heading}`.
  - Phase 1's schema bootstrap set nav labels through the same missing property, so the nav blocks show only their
    type name. Task 1 labels them as Phase 1 meant to.
- **Icons.** 17.7 has no `icon-text`: a rich text block with it showed a blank icon. `icon-paragraph`, `icon-grid`,
  `icon-layers-alt`, `icon-document` and `icon-settings` exist.
- **The rich text editor.** The Tiptap toolbar items this plan configures exist in 17.7, and the block's editor shows
  exactly them: source, H1–H3, italic, alignment, both lists, link and unlink. `Umb.Tiptap.RichTextEssentials` is only
  the document, paragraph, text and history, so the editor can write no span, font size, colour or weight;
  `text-align` is the one inline style it keeps.
- **Writing blocks through `IContentEditingService`** stores the editor's format the way the backoffice would:
  - a nested Block List as a JSON object;
  - a rich text string as `{ "markup": …, "blocks": … }`;
  - a document link `{ "type": "document", "unique": <key> }` as a `umb://document/…` UDI;
  - a dropdown as a string array.
- **`UpdateAsync` takes the node's whole state.** An update that left `metadataTitle` out cleared it, and the page
  title fell back to "Home". The content bootstrap passes the title again.
- **The baseline export** after the content bootstrap rewrote `Content/home.config` and no other file (37 items).
- **The generated models:**

  | Model | Members |
  |---|---|
  | `HomePage` | `Sections`: `BlockListModel` |
  | `RichTextBlock` | `Text`: `IHtmlEncodedString` |
  | `CardGridBlock` | `Heading`, `Columns`: `string`; `Cards`: `BlockListModel` |
  | `StackerBlock` | `Heading`: `string`; `Body`: `IHtmlEncodedString`; `Image`: `MediaWithCrops`; `Cards`: `BlockListModel` |
  | `Card` | `Heading`, `SubHeading`, `Body`, `Wash`: `string`; `Link`: `Link` |
  | `SectionSettings` | `Background`, `Width`: `string` |

  Their properties are virtual, so Moq mocks them. `BlockListItem` and `BlockListModel` have public constructors, so the
  mapping is unit-tested without a site.
- **Razor.** `section` is a Razor directive: `@foreach (var section in …)` fails with RZ2005, so the loop variable is
  `block`. An attribute whose value is null is left out, which keeps `class` off an unstyled section.
- **Tailwind.** It emits the literal classes it finds in the partials (`lg:grid-cols-4`, `gap-y-[72px]`). The padding
  C# builds for a filled ground and a full-width gutter (`p-6`, `lg:p-12`, `px-4`) has to be safelisted; a unit test
  now proves every class C# can build is.
- **Rich text rhythm.** Tailwind's reset leaves editor paragraphs touching. The Xperience home spaced them with
  `<p><br></p>`, which Tiptap does not keep; `kcc-prose` spaces them one rule apart.
- **The desk under a section.** The grain is `#app`'s first child, painted under `main`. An opaque `bg-desk` section
  covered it, which is what drew the flat rectangles in the Xperience reference (near-black in dark). A Desk section
  is now left unfilled, and those rectangles are gone in both ramps.
- **The sections' own grid.** The sections sit in a nested `full-width content-grid`, so they keep the `thin`,
  `breakout` and `full-width` columns of `Styles/Layout.css`. The grid's `gap-y-[72px]` puts them a section apart, as
  RecipeDetail's `space-y-[72px]` does its own. It clips sideways overflow too: on a phone, a tall sheet's tilt reaches
  past the screen's edge, and without the clip the page scrolls sideways.
- **One tear cycle down the page.** When every section started its own cycle, the welcome sheet and Beef, the first
  card below it, were both tear 1. So every sheet and card takes the next tear of one cycle, across sections.
  - The stacker's text sheet is sticky from `lg`, so it travels. At rest it sits beside the first card. As the section
    scrolls off, it rests beside the last card, bottoms aligned, just above the next section.
  - So the stack's cards and the first two sheets or cards below the stack skip the sheet's tear. Across a four-column
    grid, the sheet's half of the width covers two cards at most.
  - A six-card stack then repeats one tear, in its first and last cards, which never touch.
- **SSR and `v-pre`.** SSR drops the `v-pre` attributes, and editor text under them renders verbatim.
- **Save and preview** renders the draft home, blocks and all, through SSR.
- **E2E.** A card drawer's height animates, so a height read right after hover finds 0. The tests wait with
  `ToHaveCSSAsync`, which also reads the layout height: a bounding box includes the slip's tilt, which gives even a
  shut drawer about 3px.
- **The brand review.** The steward reviewed four rounds of the prototype.
  - The first was off brand. The owner then settled three questions on 2026-09-25:
    - **Section grounds keep all four options.** The owner accepts the steward's note that a filled band is un-torn
      paper and hides the grain.
    - **The home's text goes on torn sheets:** a rich text block, and the stacker's body and image.
    - **The kit's 72px rhythm replaces the padding settings,** so `sectionSettings` keeps background and width only.
  - The second found three more problems, all fixed in this plan:
    - sheets in neighbouring sections sharing a tear, fixed by the page-wide cycle;
    - one very tall sheet, fixed by splitting the placeholder into two blocks and clipping sideways overflow;
    - heavy band padding on phones, fixed by `p-6 lg:p-12`.
  - The third found one problem: the drinks text sheet and Wine, its last card, were both tear 4.
    - At rest they are far apart, but the sticky sheet comes to rest beside Wine as the section scrolls off.
    - Fixed by having the stack's cards, and the two sheets or cards below the stack, skip the sheet's tear.
  - The fourth called the fix **On brand with notes**. The notes are the owner-accepted filled bands and the wash bug
    below. Its wording fixes to `kit.md` are in Task 3.
    - It also found two repeats that only touch at a corner. Neither happens on this page, and it counted them as
      notes, not hits.
    - A stack of four or nine cards above a four-column grid of six or more cards gives that grid's first and sixth
      cards the same tear.
    - A stack of three or eight cards gives the grid's third card the sheet's tear, as the plain cycle already did.

  Two findings were not about Home:
  - `.content-grid > .thin` shrink-wrapped its content; Task 3 gives it a width.
  - Every corner wash whose radius is capped with `min()`, such as the card's `min(40%, 68px)`, computes to
    `background-image: none` in Chrome, so none has ever rendered, in the Xperience reference either. That bug is in
    the kit, and it is filed as a task of its own. The home's grid cards show no wash until it lands.

```csharp
using Umbraco.Cms.Core;
using Umbraco.Cms.Core.Models;
using Umbraco.Cms.Core.Models.ContentTypeEditing;
using Umbraco.Cms.Core.PropertyEditors;
using Umbraco.Cms.Core.Serialization;
using Umbraco.Cms.Core.Services;
using Umbraco.Cms.Core.Services.ContentTypeEditing;
using Umbraco.Cms.Core.Strings;
using Umbraco.Cms.Infrastructure.ModelsBuilder.Building;

namespace KCC.Web.Features.DevTools.Baseline;

public class HomeSchemaBootstrap(
    IDataTypeService dataTypeService,
    PropertyEditorCollection propertyEditors,
    IConfigurationEditorJsonSerializer configurationSerializer,
    IContentTypeService contentTypeService,
    IContentTypeEditingService contentTypeEditingService,
    IShortStringHelper shortStringHelper,
    IModelsGenerator modelsGenerator)
{
    private static readonly string[] Backgrounds = ["Desk", "Desk two", "Paper", "Paper two"];

    private static readonly string[] Widths = ["Thin", "Container", "Breakout", "Full width"];

    private static readonly string[] Washes = ["Peach", "Yellow", "Green", "Teal", "Sky", "Lavender", "Pink", "Red"];

    private static readonly string[] ColumnCounts = ["2", "3", "4"];

    // Only what the kit styles: no bold (one weight of everything), underline (links are the underlined thing),
    // colour, media or tables.
    private static readonly string[] RichTextExtensions =
    [
        "Umb.Tiptap.RichTextEssentials",
        "Umb.Tiptap.Heading",
        "Umb.Tiptap.Italic",
        "Umb.Tiptap.Link",
        "Umb.Tiptap.BulletList",
        "Umb.Tiptap.OrderedList",
        "Umb.Tiptap.TextAlign",
        "Umb.Tiptap.TrailingNode",
    ];

    private static readonly string[][][] RichTextToolbar =
    [
        [
            ["Umb.Tiptap.Toolbar.SourceEditor"],
            ["Umb.Tiptap.Toolbar.Heading1", "Umb.Tiptap.Toolbar.Heading2", "Umb.Tiptap.Toolbar.Heading3"],
            ["Umb.Tiptap.Toolbar.Italic"],
            ["Umb.Tiptap.Toolbar.TextAlignLeft", "Umb.Tiptap.Toolbar.TextAlignCenter", "Umb.Tiptap.Toolbar.TextAlignRight"],
            ["Umb.Tiptap.Toolbar.BulletList", "Umb.Tiptap.Toolbar.OrderedList"],
            ["Umb.Tiptap.Toolbar.Link", "Umb.Tiptap.Toolbar.Unlink"],
        ],
    ];

    public async Task<IReadOnlyList<string>> RunAsync()
    {
        var created = new List<string>();

        var textstring = Constants.DataTypes.Guids.TextstringGuid;
        var textarea = Constants.DataTypes.Guids.TextareaGuid;
        var image = Constants.DataTypes.Guids.MediaPicker3SingleImageGuid;

        var background = await EnsureDataTypeAsync(created, "KCC Section Background", Dropdown(Backgrounds));
        var width = await EnsureDataTypeAsync(created, "KCC Section Width", Dropdown(Widths));
        var wash = await EnsureDataTypeAsync(created, "KCC Wash", Dropdown(Washes));
        var columns = await EnsureDataTypeAsync(created, "KCC Card Columns", Dropdown(ColumnCounts));
        var richText = await EnsureDataTypeAsync(
            created,
            "KCC Rich Text",
            new(
                Constants.PropertyEditors.Aliases.RichText,
                "Umb.PropertyEditorUi.Tiptap",
                new() { ["extensions"] = RichTextExtensions, ["toolbar"] = RichTextToolbar, ["overlaySize"] = "medium" }));
        var optionalLink = await EnsureDataTypeAsync(
            created,
            "KCC Optional Link",
            new(Constants.PropertyEditors.Aliases.MultiUrlPicker, "Umb.PropertyEditorUi.MultiUrlPicker", new() { ["minNumber"] = 0, ["maxNumber"] = 1 }));

        var card = await EnsureElementTypeAsync(created, new("card", "Card", "icon-document")
        {
            Properties =
            [
                new("heading", "Heading", textstring, Mandatory: true),
                new("subHeading", "Subheading", textstring),
                new("body", "Body", textarea, Description: "Shown in the drawer that opens on hover, with the link."),
                new("wash", "Wash", wash, Description: "Unset leaves the card bare paper."),
                new("link", "Link", optionalLink),
            ],
        });
        var cards = await EnsureDataTypeAsync(created, "KCC Cards", BlockList(min: 1, (card, null, "{=heading}")));

        var settings = await EnsureElementTypeAsync(created, new("sectionSettings", "Section Settings", "icon-settings")
        {
            Group = "Section",
            Properties =
            [
                new("background", "Background", background, Description: "Unset is Desk, which leaves the section unfilled."),
                new("width", "Width", width, Description: "Unset is Container."),
            ],
        });

        var richTextBlock = await EnsureElementTypeAsync(created, new("richTextBlock", "Rich Text Block", "icon-paragraph")
        {
            Properties = [new("text", "Text", richText, Mandatory: true, Description: "The block is one torn sheet: split long copy across several blocks.")],
        });
        var cardGridBlock = await EnsureElementTypeAsync(created, new("cardGridBlock", "Card Grid Block", "icon-grid")
        {
            Properties =
            [
                new("heading", "Heading", textstring),
                new("columns", "Columns on wide screens", columns, Description: "Unset is 2. Narrow screens always show one."),
                new("cards", "Cards", cards, Mandatory: true),
            ],
        });
        var stackerBlock = await EnsureElementTypeAsync(created, new("stackerBlock", "Stacker Block", "icon-layers-alt")
        {
            Properties =
            [
                new("heading", "Heading", textstring, Mandatory: true),
                new("body", "Body", richText),
                new("image", "Image", image),
                new("cards", "Cards", cards, Mandatory: true, Description: "Each shows its heading, subheading and wash."),

        var sections = await EnsureDataTypeAsync(
            created,
            "KCC Home Sections",
            BlockList(
                min: 0,
                (richTextBlock, settings, "Rich text: {=text | stripHtml | truncate:60}"),
                (cardGridBlock, settings, "Card grid: {=heading}"),
                (stackerBlock, settings, "Stacker: {=heading}")));

        await AddSectionsToHomeAsync(created, sections);
        await LabelNavBlocksAsync(created);

        modelsGenerator.GenerateModels();
        return created;

    private static Guid Key(string name) => DeterministicKey.For($"kcc-baseline:{name}");

    private static DataTypeSpec Dropdown(string[] items) =>
        new(Constants.PropertyEditors.Aliases.DropDownListFlexible, "Umb.PropertyEditorUi.Dropdown", new() { ["items"] = items, ["multiple"] = false });

    // BlockListConfiguration.BlockConfiguration models only the two element keys; the label the backoffice shows is
    // more of the same JSON.
    private static DataTypeSpec BlockList(int min, params (Guid Content, Guid? Settings, string Label)[] blocks) =>
        new(
            Constants.PropertyEditors.Aliases.BlockList,
            "Umb.PropertyEditorUi.BlockList",
            new()
            {
                ["blocks"] = blocks.Select(block => new Dictionary<string, object>
                {
                    ["contentElementTypeKey"] = block.Content,
                    ["settingsElementTypeKey"] = block.Settings,
                    ["label"] = block.Label,
                }).ToArray(),
                ["validationLimit"] = new Dictionary<string, object> { ["min"] = min, ["max"] = null },
            });

    private IContentType RequireContentType(string alias) =>
        contentTypeService.Get(alias) ?? throw new InvalidOperationException($"Document type {alias} is missing; Phase 1's baseline creates it.");

    private async Task AddSectionsToHomeAsync(List<string> created, Guid sectionsKey)
    {
        var home = RequireContentType("homePage");
        if (home.PropertyTypeExists("sections"))
        {
            return;
        }

        var sections = await dataTypeService.GetAsync(sectionsKey)
            ?? throw new InvalidOperationException("KCC Home Sections is missing.");
        home.AddPropertyType(
            new PropertyType(shortStringHelper, sections, "sections") { Name = "Sections", Key = Key("property:homePage:sections"), SortOrder = 0 },
            "home",
            "Home");
        home.PropertyGroups["home"].Key = Key("container:homePage:Home");

        var result = await contentTypeService.UpdateAsync(home, Constants.Security.SuperUserKey);
        if (!result.Success)
        {
            throw new InvalidOperationException($"Updating homePage failed: {result.Result}.");
        }

        created.Add("homePage: sections");
    }

    // Phase 1's schema bootstrap could not set these labels through BlockConfiguration, so the backoffice lists every
    // nav block by its type name alone.
    private async Task LabelNavBlocksAsync(List<string> created)
    {
        var navItems = await dataTypeService.GetAsync("KCC Nav Items")
            ?? throw new InvalidOperationException("KCC Nav Items is missing; Phase 1's baseline creates it.");
        if (configurationSerializer.Serialize(navItems.ConfigurationData).Contains("\"label\"", StringComparison.Ordinal))
        {
            return;
        }

        navItems.ConfigurationData = BlockList(
            min: 0,
            (RequireContentType("navLink").Key, null, "{=displayText}"),
            (RequireContentType("navGroup").Key, null, "{=displayText}")).Configuration;

        var result = await dataTypeService.UpdateAsync(navItems, Constants.Security.SuperUserKey);
        if (!result.Success)
        {
            throw new InvalidOperationException($"Labelling KCC Nav Items failed: {result.Status}.");
        }

        created.Add("KCC Nav Items: labels");
    }

    private async Task<Guid> EnsureDataTypeAsync(List<string> created, string name, DataTypeSpec spec)
    {
        var key = Key($"dataType:{name}");
        if (await dataTypeService.GetAsync(key) is not null)
        {
            return key;
        }

        var editor = propertyEditors[spec.EditorAlias] ?? throw new InvalidOperationException($"No property editor is registered as {spec.EditorAlias}.");
        var dataType = new DataType(editor, configurationSerializer)
        {
            Key = key,
            Name = name,
            EditorUiAlias = spec.EditorUiAlias,
            DatabaseType = ValueTypes.ToStorageType(editor.GetValueEditor().ValueType),
            ConfigurationData = spec.Configuration,
        };

        var result = await dataTypeService.CreateAsync(dataType, Constants.Security.SuperUserKey);
        if (!result.Success)
        {
            throw new InvalidOperationException($"Creating data type {name} failed: {result.Status}.");
        }

        created.Add(name);
        return key;
    }

    private async Task<Guid> EnsureElementTypeAsync(List<string> created, TypeSpec spec)
    {
        var key = Key($"contentType:{spec.Alias}");
        if (contentTypeService.Get(key) is not null)
        {
            return key;
        }

        var containerKey = Key($"container:{spec.Alias}:{spec.Group}");
        var model = new ContentTypeCreateModel
        {
            Key = key,
            Alias = spec.Alias,
            Name = spec.Name,
            Icon = spec.Icon,
            IsElement = true,
            Containers = [new ContentTypePropertyContainerModel { Key = containerKey, Name = spec.Group, Type = "Group", SortOrder = 0 }],
            Properties = spec.Properties.Select((property, index) => new ContentTypePropertyTypeModel
            {
                Key = Key($"property:{spec.Alias}:{property.Alias}"),
                ContainerKey = containerKey,
                SortOrder = index,
                Alias = property.Alias,
                Name = property.Name,
                Description = property.Description,
                DataTypeKey = property.DataType,
                Validation = new PropertyTypeValidation { Mandatory = property.Mandatory },
                Appearance = new PropertyTypeAppearance(),
            }).ToList(),
        };

        var result = await contentTypeEditingService.CreateAsync(model, Constants.Security.SuperUserKey);
        if (!result.Success)
        {
            throw new InvalidOperationException($"Creating element type {spec.Alias} failed: {result.Status}.");
        }

        created.Add(spec.Alias);
        return key;
    }

    private sealed record DataTypeSpec(string EditorAlias, string EditorUiAlias, Dictionary<string, object> Configuration);

    private sealed record PropertySpec(string Alias, string Name, Guid DataType, bool Mandatory = false, string Description = null);

    private sealed record TypeSpec(string Alias, string Name, string Icon)
    {
        public string Group { get; init; } = "Content";

        public IReadOnlyList<PropertySpec> Properties { get; init; } = [];
    }
}
```

The bootstrap makes these choices:
- **The card is Xperience's `CardItem`**, reusable no longer: each grid or stacker holds its own cards. A card's body
  and link show in the drawer that opens on hover; the stacker shows heading, subheading and wash only, as its component
  always has.
- **The rich text editor offers only what the kit renders on-brand.** Bold, underline, colour, media, tables and code
  are left out, and the editor drops them from pasted text.
- **`KCC Cards` asks for at least one card.** An empty grid or stacker renders nothing useful.
- **The stacker's heading is required,** and the card grid's is optional, as in the Xperience widgets.

```csharp
using KCC.Web.Features.Models.Generated;

namespace KCC.Web.Features.Pages.Home;

// Tailwind never scans .cs files: every class built here is in the safelist in Styles/TailwindConfig.css.
public static class SectionStyle
{
    public static string Classes(SectionSettings settings) => Classes(settings?.Background, settings?.Width);

    public static string Classes(string background, string width)
    {
        var fill = Fill(background);
        var filled = fill.Length > 0;
        return string.Join(' ', new[] { Width(width, filled), fill, filled ? "p-6 lg:p-12" : string.Empty }.Where(name => name.Length > 0));
    }

    public static string Wash(string wash) => string.IsNullOrWhiteSpace(wash) ? string.Empty : $"bg-{wash.ToLowerInvariant()}";

    // A full-width section has no column gutter of its own; a filled one takes its padding instead.
    private static string Width(string width, bool filled) => width switch
    {
        "Thin" => "thin",
        "Breakout" => "breakout",
        "Full width" => filled ? "full-width" : "full-width px-4",
        _ => string.Empty,
    };

    // A section on the desk stays unfilled: an opaque desk fill would cover the grain that sits under the page.
    private static string Fill(string background) => background switch
    {
        "Desk two" => "bg-desk-2",
        "Paper" => "bg-paper",
        "Paper two" => "bg-paper-2",
        _ => string.Empty,
    };
}
```

```csharp
using KCC.Web.Features.Models.Generated;
using Umbraco.Cms.Core.Models;
using Umbraco.Cms.Core.Models.Blocks;
using Umbraco.Cms.Core.Models.PublishedContent;

namespace KCC.Web.Features.Pages.Home;

public static class HomeSections
{
    public static IReadOnlyList<HomeSection> From(BlockListModel sections)
    {
        var tears = new TearCycle();
        var result = new List<HomeSection>();
        foreach (var block in sections ?? Enumerable.Empty<BlockListItem>())
        {
            var section = Section(block.Content, SectionStyle.Classes(block.Settings as SectionSettings), tears);
            if (section is not null)
            {
                result.Add(section);
            }
        }

        return result;
    }

    private static HomeSection Section(IPublishedElement content, string classes, TearCycle tears) => content switch
    {
        RichTextBlock richText => new RichTextSection(classes, tears.Next(), richText.Text?.ToHtmlString() ?? string.Empty),
        CardGridBlock grid => new CardGridSection(
            classes,
            grid.Heading,
            Columns(grid.Columns),
            Elements<Card>(grid.Cards).Select(card => new HomeCard(card.Heading, card.SubHeading, card.Body, SectionStyle.Wash(card.Wash), Link(card.Link), tears.Next())).ToList()),
        StackerBlock stacker => Stacker(stacker, classes, tears),
        _ => null,
    };

    private static StackerSection Stacker(StackerBlock stacker, string classes, TearCycle tears)
    {
        var body = stacker.Body?.ToHtmlString();
        var image = Image(stacker.Image);
        var cards = Elements<Card>(stacker.Cards).ToList();
        var sheetTear = 0;
        if (!string.IsNullOrWhiteSpace(body) || image is not null)
        {
            sheetTear = tears.Next();

            // The sheet is sticky on wide screens, so it passes every card in the stack and comes to rest above the
            // next section. Grids stop at four columns, so its half of the width covers two of that section's sheets
            // or cards at most. None of them may take its tear.
            tears.Avoid(sheetTear, cards.Count + 2);
        }

        return new StackerSection(
            classes,
            sheetTear,
            stacker.Heading,
            body,
            image,
            cards.Select(card => new StackerCard(card.Heading, card.SubHeading ?? string.Empty, SectionStyle.Wash(card.Wash), tears.Next())).ToList());
    }

    private static int Columns(string columns) => int.TryParse(columns, out var count) && count is >= 2 and <= 4 ? count : 2;

    private static HomeLink Link(Link link) =>
        link?.Url is { Length: > 0 } url ? new HomeLink(link.Name ?? string.Empty, url, link.Target) : null;

    private static HomeImage Image(MediaWithCrops image) =>
        image is null ? null : new HomeImage(HomeImages.StackerUrl(image), image.Name);

    private static IEnumerable<T> Elements<T>(BlockListModel blocks) =>
        (blocks ?? Enumerable.Empty<BlockListItem>()).Select(block => block.Content).OfType<T>();

    // One tear cycle runs down the whole page, through sheets and cards alike, so a sheet never shares its tear with
    // the one beside it, even across two sections.
    private sealed class TearCycle
    {
        private int taken;
        private int avoided;
        private int drawsLeft;

        public int Next()
        {
            var tear = Take();
            if (drawsLeft > 0)
            {
                drawsLeft--;
                if (tear == avoided)
                {
                    tear = Take();
                }
            }

            return tear;
        }

        public void Avoid(int tear, int draws)
        {
            avoided = tear;
            drawsLeft = draws;
        }

        private int Take() => (taken++ % 6) + 1;
    }
}
```

The core Image media type has no alt-text field, so the image's alt is its media name. `TearCycle` hands out the tears
in reading order: a section's sheet, then its cards, then the next section's. After a stacker's sheet, `Avoid` has the
next `cards.Count + 2` draws pass over that sheet's tear: the stack's cards, and the first two sheets or cards below
them.
